1. Введение

Программное изделие, разрабатываемое в рамках данной работы, представляет собой мобильное приложение «ArtSphere Auction», предназначенное для платформы iOS. Оно представляет собой площадку для проведения аукционов цифровых произведений искусства (NFT), обеспечивающую удобное взаимодействие между авторами и коллекционерами.

Основная область применения приложения — рынок цифрового искусства (NFT), где важную роль играет визуализация произведений и возможность участия в аукционах в реальном времени. «ArtSphere Auction» предоставляет пользователям возможность просматривать произведения искусства в интерактивном 3D-режиме с применением карт нормалей и displacement-маппинга, участвовать в аукционах с поддержкой WebSocket-уведомлений, создавать собственные NFT и формировать коллекции. Приложение ориентировано как на авторов цифрового искусства, позволяя им выставлять свои произведения на аукцион, так и на коллекционеров, предоставляя им инструменты для поиска, оценки и приобретения NFT.


2. Основание для разработки

Тема разработки: «Мобильное приложение для аукциона цифровых произведений искусства на платформе iOS».
Условное обозначение проекта: «ArtSphere Auction».

Основанием для разработки является задание на выпускную квалификационную работу, подписанное руководителем выпускной работы и утверждённое заведующим кафедрой ИУ5 МГТУ им. Н.Э. Баумана.


3. Назначение разработки

Назначением разработки является создание мобильного приложения «ArtSphere Auction» для платформы iOS, представляющего собой специализированную площадку для проведения аукционов цифровых произведений искусства. Основной целью является обеспечение удобства взаимодействия между авторами произведений и коллекционерами.

Приложение предназначено для:

— коллекционеров, которые могут просматривать произведения искусства в интерактивном 3D-режиме, участвовать в аукционах в реальном времени, формировать персональные коллекции, отслеживать историю ставок и общаться с авторами через встроенный чат;

— авторов (художников), которые могут создавать NFT путём загрузки изображений с автоматической конвертацией в 3D, выставлять произведения на аукцион с настройкой параметров (начальная цена, длительность), получать уведомления о ставках и взаимодействовать с покупателями.

Эксплуатационное назначение заключается в обеспечении стабильной работы на мобильных устройствах с операционной системой iOS. Приложение работает по модели клиент-сервер, где серверная часть построена на фреймворке Vapor (Swift) с ORM Fluent. Для обмена данными используется REST API и WebSocket для доставки уведомлений в реальном времени. База данных PostgreSQL обеспечивает хранение информации о пользователях, произведениях, аукционах и ставках. Облачное хранилище Cloudflare R2 (S3-совместимое) используется для хранения изображений произведений и аватаров пользователей.


4. Требования к программе или программному изделию

4.1. Требования к функциональным характеристикам

4.1.1. Регистрация и аутентификация

4.1.1.1. Пользователь должен иметь возможность зарегистрироваться, указав имя пользователя, адрес электронной почты и пароль. После успешной регистрации система автоматически выполняет вход и перенаправляет пользователя на главный экран.

4.1.1.2. Пользователь должен иметь возможность войти в систему, введя адрес электронной почты и пароль. При успешной аутентификации JWT-токен сохраняется в Keychain устройства для последующего автоматического входа.

4.1.1.3. При запуске приложения система должна автоматически проверять наличие сохранённого JWT-токена и, при его наличии и валидности, пропускать экран авторизации.

4.1.1.4. Пользователь должен иметь возможность выйти из учётной записи. При выходе JWT-токен удаляется из Keychain, и пользователь перенаправляется на экран авторизации.

4.1.2. Главный экран (лента аукционов)

4.1.2.1. На главном экране отображается лента активных аукционов в виде карточек с 3D-параллакс эффектом, реагирующим на наклон устройства.

4.1.2.2. Каждая карточка аукциона содержит: изображение произведения, название, имя автора, текущую ставку, обратный отсчёт до окончания аукциона и количество ставок.

4.1.2.3. Карточки появляются с анимацией «staggered» (поочерёдное появление).

4.1.2.4. Пользователь может обновить ленту жестом pull-to-refresh (потянуть вниз).

4.1.2.5. В верхней части экрана отображается секция «Популярное» (Featured) с горизонтальной прокруткой.

4.1.2.6. Пользователь может открыть поиск произведений по названию и имени автора.

4.1.2.7. В навигационной панели отображается кнопка уведомлений с числовым индикатором непрочитанных уведомлений. При нажатии открывается список уведомлений.

4.1.2.8. При нажатии на карточку аукциона пользователь переходит на экран детальной информации.

4.1.3. Детальная информация о произведении и аукционе

4.1.3.1. На экране детальной информации отображается изображение произведения в режиме 2D.

4.1.3.2. Пользователь может переключиться в режим интерактивного 3D-просмотра нажатием кнопки «3D». В данном режиме изображение отображается с применением карт нормалей (Sobel-фильтр, Accelerate framework) и displacement-маппинга для имитации рельефа мазков.

4.1.3.3. При повторном нажатии кнопки «3D» (в состоянии «2D») изображение возвращается в двумерный режим.

4.1.3.4. В режиме 3D пользователь может включить визуализацию карты сложности текстуры (heatmap) нажатием соответствующей кнопки.

4.1.3.5. Нажатие на изображение в режиме 3D открывает полноэкранный 3D-просмотр с возможностью вращения камеры вокруг произведения жестами (orbit camera). Поддерживается загрузка и отображение USDZ-моделей.

4.1.3.6. Под изображением отображается информация: название произведения, имя автора (с возможностью перехода на профиль автора), блокчейн и категория.

4.1.3.7. Отображается описание произведения.

4.1.3.8. Пользователь может поставить «лайк» произведению нажатием кнопки-сердца. Рядом отображается счётчик лайков.

4.1.3.9. Отображается счётчик комментариев с возможностью перехода на вкладку комментариев.

4.1.3.10. Кнопка «Поделиться» позволяет отправить произведение другому пользователю через встроенный чат.

4.1.3.11. Кнопка «Добавить в коллекцию» (папка) открывает лист выбора коллекции. Пользователь выбирает коллекцию, и произведение добавляется в неё. Если произведение уже в коллекции, отображается галочка, и повторное нажатие удаляет его из коллекции.

4.1.3.12. Кнопка «Избранное» (сердце) в навигационной панели добавляет/удаляет произведение из списка избранного.

4.1.3.13. Блок аукциона отображает: текущую ставку (или итоговую цену для завершённых), обратный отсчёт до окончания (или статус «Закрыт»), кнопку «Сделать ставку».

4.1.3.14. Для завершённых аукционов отображается баннер с результатом: «Аукцион завершён», имя победителя и сумма, или индикатор «Вы выиграли это произведение!» для текущего пользователя.

4.1.3.15. Экран содержит четыре вкладки: «Обзор», «Ставки», «Комментарии», «Детали».

4.1.3.16. Вкладка «Обзор» отображает: художник, дата создания, категория, токен ID, блокчейн, статус резервной цены.

4.1.3.17. Вкладка «Ставки» отображает историю ставок в хронологическом порядке (от новых к старым). Каждая ставка содержит имя пользователя (с возможностью перехода на профиль), дату/время и сумму. Ставки текущего пользователя выделены цветом с пометкой «Вы».

4.1.3.18. Вкладка «Комментарии» позволяет просматривать комментарии других пользователей (аватар, имя, дата, текст) и оставлять свои комментарии через текстовое поле ввода.

4.1.3.19. Вкладка «Детали» отображает: начальная цена, резервная цена, дата начала, дата окончания, общее количество ставок, минимальная следующая ставка, сложность текстуры.

4.1.4. Размещение ставок

4.1.4.1. Пользователь может сделать ставку на активный аукцион нажатием кнопки «Сделать ставку». Открывается лист ввода суммы ставки.

4.1.4.2. Система отображает текущую ставку и минимально допустимую сумму следующей ставки (с учётом bidStep сервера).

4.1.4.3. При успешном размещении ставки пользователь получает подтверждение и ставка мгновенно отображается в истории ставок.

4.1.4.4. При отсутствии сетевого подключения ставка помещается в локальную очередь (BidQueue). Пользователь видит индикатор «Ставка в очереди — синхронизируется при подключении».

4.1.4.5. При восстановлении сетевого подключения ставки из очереди автоматически отправляются на сервер пакетом (batch sync) с экспоненциальным backoff.

4.1.4.6. Новые ставки других пользователей отображаются в реальном времени через WebSocket-соединение.

4.1.5. Уведомления

4.1.5.1. Система уведомлений информирует пользователя о: новых ставках на аукционы, в которых он участвует; выигрыше аукциона; перебитии его ставки; завершении аукциона; создании нового NFT.

4.1.5.2. Уведомления доставляются в реальном времени через WebSocket.

4.1.5.3. Пользователь может просматривать историю уведомлений на отдельном экране, доступном с главного экрана.

4.1.6. Сообщения (чат)

4.1.6.1. Вкладка «Сообщения» отображает список диалогов с другими пользователями, отсортированный по дате последнего сообщения.

4.1.6.2. При нажатии на диалог открывается экран переписки с историей сообщений.

4.1.6.3. Пользователь может отправить текстовое сообщение, введя текст и нажав кнопку отправки.

4.1.6.4. Пользователь может поделиться произведением через чат — произведение отображается как карточка-вложение в сообщении.

4.1.6.5. Пользователь может начать новый диалог: нажатие кнопки «Новый диалог» открывает экран поиска пользователей по имени. При выборе пользователя создаётся диалог.

4.1.7. Создание NFT

4.1.7.1. Нажатие на вкладку «Создать» в панели навигации открывает экран создания NFT.

4.1.7.2. На первом шаге пользователь выбирает изображение из фотогалереи устройства (PNG, JPG до 50 МБ). Система загружает изображение на сервер (через API → Cloudflare R2).

4.1.7.3. На втором шаге пользователь заполняет: название произведения, описание, начальную цену в ETH и длительность аукциона (от 1 часа до 7 дней с помощью слайдера).

4.1.7.4. На третьем шаге отображается 3D-превью загруженного произведения с применением карт нормалей.

4.1.7.5. При нажатии кнопки создания произведение публикуется: создаётся запись аукциона на сервере, и пользователь видит экран подтверждения с возможностью перейти на ленту.

4.1.8. Коллекции

4.1.8.1. Вкладка «Коллекция» отображает все произведения, принадлежащие пользователю (выигранные на аукционах или созданные им).

4.1.8.2. Произведения отображаются в виде сетки карточек. При нажатии на карточку открывается детальная информация.

4.1.8.3. Пользователь может просматривать свои именованные коллекции (раздел «Коллекции» над сеткой).

4.1.8.4. Пользователь может создать новую коллекцию: нажатие кнопки «+» открывает форму ввода названия и описания (необязательно).

4.1.8.5. Пользователь может редактировать существующую коллекцию (изменение названия и описания).

4.1.8.6. Пользователь может удалить коллекцию.

4.1.8.7. Содержимое коллекций обновляется жестом pull-to-refresh.

4.1.9. Профиль пользователя

4.1.9.1. Вкладка «Профиль» отображает информацию о текущем пользователе: аватар, имя, баланс кошелька в ETH.

4.1.9.2. Отображается секция статистики: количество собственных NFT, количество избранных, количество выигранных аукционов, количество активных ставок.

4.1.9.3. Пользователь может редактировать профиль: изменить отображаемое имя, описание (bio) и аватар. Аватар загружается с устройства и сохраняется локально (Documents/user_avatar.jpg) и на сервер (Cloudflare R2).

4.1.9.4. Пользователь может переключить тему оформления: «Системная», «Светлая», «Тёмная».

4.1.9.5. Пользователь может переключить язык интерфейса: русский или английский.

4.1.9.6. Пользователь может экспортировать метрики использования приложения.

4.1.9.7. Данные профиля обновляются жестом pull-to-refresh.

4.1.10. Профиль другого пользователя

4.1.10.1. Из различных экранов (ставки, комментарии, чат) пользователь может перейти на профиль другого пользователя.

4.1.10.2. Профиль другого пользователя отображает: аватар, имя, произведения автора и аукционную активность.

4.1.10.3. Пользователь может подписаться на другого пользователя (кнопка «Подписаться» / «Отписаться»).

4.1.11. 3D-визуализация произведений

4.1.11.1. Каждое произведение может быть просмотрено в интерактивном 3D-режиме на основе SceneKit.

4.1.11.2. Из 2D-изображения автоматически генерируются карты нормалей с помощью Sobel-фильтра (Accelerate framework), что создаёт эффект рельефа мазков.

4.1.11.3. Применяется displacement-маппинг для физического смещения вершин геометрии.

4.1.11.4. Полноэкранный 3D-просмотр поддерживает свободное вращение камеры (orbit turntable), масштабирование и загрузку USDZ-моделей с сервера.

4.1.11.5. Используется физически корректное освещение (PBR) с ключевым, заполняющим, контровым и рассеянным источниками света.

4.1.12. Оффлайн-режим

4.1.12.1. Приложение должно обрабатывать сетевые ошибки и отображать информативные сообщения пользователю.

4.1.12.2. Ставки, сделанные без сетевого подключения, сохраняются в локальной очереди и автоматически синхронизируются при восстановлении связи.

4.1.12.3. Мониторинг состояния сети осуществляется через NWPathMonitor, обеспечивая автоматическую синхронизацию.

4.1.13. Поддержка локализации и темы

4.1.13.1. Приложение поддерживает два языка интерфейса: русский и английский. Переключение языка доступно в настройках профиля и применяется мгновенно без перезапуска приложения.

4.1.13.2. Приложение поддерживает три режима оформления: системный (следует настройкам iOS), светлый и тёмный. Переключение применяется мгновенно.


4.2. Требования к надёжности

4.2.1. Приложение должно обеспечивать бесперебойную работу при высокой нагрузке и одновременном участии нескольких пользователей в одном аукционе.

4.2.2. WebSocket-соединение должно автоматически переподключаться при разрыве связи с использованием экспоненциального backoff (базовый интервал 1 с, максимум 5 попыток).

4.2.3. Данные аутентификации (JWT-токен) должны храниться в Keychain устройства в защищённом виде.

4.2.4. Пароли пользователей должны храниться на сервере в хэшированном виде (Bcrypt).


4.3. Условия эксплуатации

4.3.1. Пользовательское приложение предназначено для работы на устройствах с iOS версии 16.0 и выше.

4.3.2. Серверная часть развёрнута на облачной платформе Railway с автоматическим масштабированием.

4.3.3. Должна быть возможность работы как при наличии сетевого подключения (Wi-Fi, сотовая связь), так и в оффлайн-режиме с ограниченным функционалом (очередь ставок).

4.3.4. Интерфейс адаптирован для различных размеров экранов iPhone.


4.4. Требования к составу и параметрам технических средств

4.4.1. Клиентская часть: iPhone с iOS 16.0+, процессор Apple A11 и выше.

4.4.2. Серверная часть: фреймворк Vapor 4 (Swift), ORM Fluent, JWT-аутентификация.

4.4.3. База данных: PostgreSQL 16 с TLS-шифрованием соединений.

4.4.4. Хранилище файлов: Cloudflare R2 (S3-совместимое хранилище) для изображений произведений и аватаров.

4.4.5. Коммуникация: REST API (HTTPS) для CRUD-операций, WebSocket (WSS) для уведомлений в реальном времени.
