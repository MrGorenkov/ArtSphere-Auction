## 🔴 БЛОК A — критичные правки по замечаниям комиссии

### A1. Лёгкие фиксы — 1 день

- [ ] **Фильтр завершённых аукционов в ленте.** На бекенде в `AuctionController.index` фильтр `WHERE status='active' AND end_time > NOW()`. На клиенте — `auction.isActive` перед записью в `auctions`.
- [ ] **Переименовать карусель ХИТ** → «Скоро завершатся». `L10n.featured` и `L10n.featuredBadge`.
- [ ] **Ставки на новые/конкретные картины не проходят.** Найти причину: проверить через Console.app логи Sancho при попытке ставки. Скорее всего: `currentBid=0` для свежесозданных артворков ломает `minimumNextBid` формулу.
- [ ] **Завершённые лоты — в Историю аукционов** (Profile → Auction History), а не в ленту.

### A2. WebSocket стабильность — полдня

- [ ] Подписаться на `UIApplication.didBecomeActiveNotification` в `WebSocketService` → гарантированный reconnect обоих каналов при возврате из фона
- [ ] Подписаться на `UIApplication.willResignActiveNotification` → корректное закрытие соединения с `goingAway`
- [ ] Логировать каждое подключение/разрыв в `MetricsService` для последующего анализа
- [ ] Снизить keep-alive интервал с 30с до 15с

### A3. Auto-broker — серверная сторона — 1 день

Сейчас автоматическое перебитие работает только когда iPhone открыт. На сервере перенесём:

- [ ] Таблица `auto_broker_settings (user_id, auction_id, max_amount, created_at)`
- [ ] При `POST /auctions/:id/auto-broker` — записать в эту таблицу (вместо текущего stub'а)
- [ ] При вставке новой ставки в `bids` — триггер БД или handler в `BidController.create`, который ищет в `auto_broker_settings` все настройки на этот auction с `max_amount > bid.amount + auction.bid_step` и автоматически создаёт контр-ставку
- [ ] Контр-ставка broadcast'ится в WS как обычное `new_bid` событие
- [ ] При успешной контр-ставке выслать создателю auto-broker уведомление через `/ws/user/:userId`

### A4. Замена Sobel → Laplacian — полдня

**Уточни у научника точное название** алгоритма который рекомендует комиссия.

**Если Лапласиан:**
- [ ] В `NormalMapGenerator.swift` заменить две Sobel-свёртки (Gx, Gy) на одну Laplacian (`[0,1,0; 1,-4,1; 0,1,0]`)
- [ ] Адаптировать формулу нормали — Лапласиан даёт скалярное значение, а не вектор. Нужна модификация: `dx`, `dy` через дифференцирование Лапласианом по X и Y отдельно. Или использовать Marr-Hildreth (Laplacian of Gaussian).

**Если MiDaS (нейронка):**
- [ ] Скачать CoreML-версию MiDaS (~50МБ)
- [ ] Добавить в проект, использовать `MLModel` для inference
- [ ] Output → реальная depth map → использовать как displacement
- [ ] **Это качественно лучше:** реальная глубина, а не имитация рельефа мазков
- [ ] 2 дня работы

### A5. Heatmap UX — полдня

- [ ] **Overlay-режим:** показывать heatmap как полупрозрачный слой (~50% прозрачности) поверх оригинала. Слайдер регулирует прозрачность.
- [ ] **Легенда:** цветовая шкала справа «низкая → высокая детализация»
- [ ] **Численная метрика:** показывать средний `texture_complexity` под изображением (например 0.42)
- [ ] (Опц.) **Тач:** нажатие на пиксель показывает значение градиента в этой точке

### A6. Админка macOS — расширение — 1 день

- [ ] Серверный `DELETE /admin/auctions/:id` (cascade на bids, transactions)
- [ ] В `AdminAuctionDetailView` кнопка «Удалить» с алертом подтверждения

## 🟣 БЛОК B — TON блокчейн (без реальных денег) — 4-5 дней

### Архитектурное решение

**TON Testnet + смарт-контракт TEP-62 + TON Connect 2.0.** Все транзакции реальные, видны в эксплорере `testnet.tonscan.org`, но монеты тестовые (получаются бесплатно через faucet-бот). На защите комиссия видит **настоящий блокчейн**, а не имитацию.

### B1. Смарт-контракт

- [ ] Установить TON Blueprint: `npm create ton@latest`
- [ ] Выбрать шаблон `nft-collection` (TEP-62 готовый)
- [ ] Деплой в testnet через faucet wallet
- [ ] Сохранить адрес коллекции — это будет наш `master_contract_address`

### B2. iOS интеграция TON Connect

- [ ] Добавить SDK [TonConnectSwift](https://github.com/tonkeeper/wallet-api-spec) или альтернатива
- [ ] В Профиль добавить кнопку **«Подключить кошелёк»** — открывает Tonkeeper через deeplink
- [ ] Сохранить `wallet_address` пользователя после успешного подключения
- [ ] Показывать balance через RPC: `runGetMethod('seqno')` + `runGetMethod('get_wallet_data')` на адресе

### B3. Mint через смарт-контракт

- [ ] Заменить `NFTTokenController.mint` логику: вместо генерации случайного адреса — собрать сообщение для контракта `nft-collection`, отправить через TON Connect (юзер подписывает в Tonkeeper)
- [ ] После подтверждения транзакции (через polling RPC) — записать в БД реальный `token_id_on_chain` (берём из NFT item address)
- [ ] Показывать ссылку на эксплорер: `https://testnet.tonscan.org/nft/{address}`

### B4. Bid логика — гибрид

- [ ] **Обычные ставки** остаются на сервере (для скорости и offline-режима)
- [ ] **Финальная покупка** (когда таймер истёк, есть winner) — формируется on-chain транзакция передачи NFT от seller к winner
- [ ] Передача оплачивается через `transfer` метод nft-item контракта

### B5. Balance отображение

- [ ] На главном экране Профиля показать «Test TON: 12.5» — баланс через RPC
- [ ] Кнопка **«Получить тестовые TON»** — deeplink на `https://t.me/testgiver_ton_bot`

### B6. Документирование

- [ ] Скриншоты транзакций в `testnet.tonscan.org` для РПЗ
- [ ] Схема взаимодействия iOS ↔ TON Connect ↔ Tonkeeper ↔ Smart Contract ↔ TON Network
